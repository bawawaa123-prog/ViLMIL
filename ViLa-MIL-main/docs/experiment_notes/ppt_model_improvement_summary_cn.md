# PPT 汇报建议（当前版本）

本文档已按当前仓库状态更新。

当前代码库保留的是干净的 `BiomedCLIP` 基线，不再包含以下增强实现：

- dynamic prompt retrieval
- VCP / HyperPrompt
- RAG / LLM rewrite

因此，如果你现在要做汇报，建议把重点放在“基线能力、实验设置、结果分析、后续改进方向”，而不是把已经移除的旧功能继续当作当前方法描述。

## 1. 建议的汇报主线

### 1.1 方法主干

可以把当前方法概括成下面四点：

1. 使用 BiomedCLIP 预提取双尺度病理 patch 特征
2. 使用双尺度文本 prompt 表达类别语义
3. 使用 ViLa-MIL 结构做低倍 / 高倍特征聚合
4. 通过图文对齐完成分类

一句话版本：

```text
当前系统是一个基于 BiomedCLIP 语义空间的双尺度 ViLa-MIL 基线模型。
```

## 2. 模型亮点怎么讲

### 2.1 从原始 CLIP 切到 BiomedCLIP

这部分是当前最稳定、最合理、也最适合讲清楚的升级点。

可以强调：

- BiomedCLIP 的医学语义先验更强
- 文本编码器更适配病理描述
- 图像特征维度更紧凑
- 作为病理任务基线更自然

### 2.2 双尺度输入

可以强调：

- 5x 更偏结构信息
- 20x 更偏细胞学细节
- 双尺度 prompt 与双尺度特征分支对应

## 3. 实验部分建议怎么讲

### 3.1 先讲基线

建议先固定讲清楚：

- 数据集
- split 方式
- 双尺度特征来源
- 双尺度 prompt 文件
- 训练轮数、学习率、seed
- AUC / ACC / F1

### 3.2 再讲你之前做过的增强尝试

如果你仍然想在 PPT 中提到旧增强路线，建议明确改成：

```text
我们曾尝试过若干提示增强方向，但当前代码已回退到干净基线，后续将基于基线重新审视这些设计。
```

这样讲比较稳，不会让听众误以为这些旧模块仍然是当前主系统的一部分。

## 4. 当前阶段更推荐的结论表述

建议用下面这类话术：

### 4.1 结论版本一

```text
当前最可靠的系统版本是 BiomedCLIP 双尺度 ViLa-MIL 基线。
在完成主链路清理后，训练与评估流程已经可以稳定运行，后续改进将以该基线为唯一参照。
```

### 4.2 结论版本二

```text
相比继续叠加复杂提示增强，当前阶段更重要的是先保证基线闭环稳定、可复现、可公平比较。
```

## 5. 后续工作怎么讲更合理

推荐按下面顺序讲：

1. 先稳定复现 BiomedCLIP 基线
2. 统一 split、训练预算、评估口径
3. 在干净基线上逐个验证新改动是否真的有收益

不建议再讲成：

```text
接下来直接继续堆更多提示增强模块
```

因为这会弱化你这次“先回归基线、再重新验证”的正确策略。

## 6. 一页可直接放 PPT 的精简版本

你可以直接放下面这段：

```text
当前系统采用 BiomedCLIP 作为医学语义底座，结合双尺度病理特征与双尺度文本提示，通过 ViLa-MIL 完成图文对齐与分类。
为保证实验可复现和后续改进可比较，我们已将训练与评估链路清理回干净基线版本，并将其作为后续所有改动的统一参照。
```

## 7. 当前文档定位

这份文档现在只服务于“当前基线汇报”。

如果以后你重新设计并重新验证新的增强方法，建议新开一份独立文档，而不是继续在这份基线汇报文档上追加旧路线说明。
